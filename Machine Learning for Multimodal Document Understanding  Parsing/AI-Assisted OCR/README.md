
1. Document Parsing / AI Document Parsing
Best for: Technical / developer context.

### Definition: 
The act of ingesting unstructured or semi-structured files (PDFs, images, docx, code files) and breaking them down into clean, structured digital formats (JSON, Markdown, plain text, ASTs).

#### Common usage: 
"We use an LLM-based document parser to pull code blocks and tables from technical PDFs."

2. Intelligent Document Processing (IDP) or Document AI
Best for: Enterprise / industry context.

### Definition: 
An enterprise term for workflows that combine OCR, Vision-Language Models (VLMs), and LLMs to digitize, extract, classify, and format text, key-value pairs, tables, and images from document pipelines.

#### Common usage: 
"Our IDP platform automatically extracts invoices and code samples from incoming tickets."

3. Structured Data Extraction / Information Extraction (IE)
Best for: Data science & prompt engineering context.

### Definition: 
The targeted process of taking raw text/visual data from files and forcing the AI model to convert it into a target schema (such as JSON, Pydantic objects, or database records).

#### Common usage: 
"We implemented structured extraction to output extracted tables and source code directly into JSON."

### Specialized Sub-Terms
Depending on the source file format and method, you will also hear:

#### Multimodal Document Understanding / Parsing: 
When using Vision-Language Models (VLMs like GPT-4o, Claude 3.5 Sonnet, or Gemini) to "see" page layouts, visual tables, and embedded code diagrams rather than relying purely on plain text.

#### AI-Assisted OCR / VLM-OCR: 
When using visual AI models instead of traditional OCR (Tesseract) to transcribe scanned PDFs/images into clean Markdown or text.

#### Code Mining / Code Extraction: 
Specifically extracting code blocks, snippets, or Abstract Syntax Trees (ASTs) from documentation or repos.
